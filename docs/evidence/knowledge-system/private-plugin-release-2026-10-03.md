# Private Content Registrar plugin release candidate

The installed Content Registrar Knowledge plugin can now be projected into a versioned, deterministic local marketplace archive. `tools/knowledge-release.mjs` accepts only an absolute, externally digest-pinned standalone plugin artifact whose source revision is clean. It writes an exclusive `.tar.gz` containing one plugin, `.agents/plugins/marketplace.json`, `README.md`, and `RELEASE.json`. The release checker requires a separately supplied archive SHA256 before parsing, then refuses noncanonical archive bytes, links, unsafe or duplicate paths, wrong marketplace metadata, inventory changes, and mismatched nested Registrar/runtime manifests. It does not read a TypeSafe key or contact Jev.

The release is built through `workflow-runtime:knowledge-release-package`. At clean candidate commit `5e3ca9543e1d898b98272e4b36eabc92fd7b0122`, two independent package runs from plugin manifest SHA256 `886141c4b11d81be13749dc96338a77f855c8286ca68bdb982acd85c4bbb6671` produced byte-identical 473,599-byte archives, SHA256 `f103ec13b922cd5e8a7edc3662642fb0003c985d90124b0ceea5b300ceabc6b2`. The archive checker passed before extraction. The committed Nx `knowledge-release-test` passed 2/2: a second deterministic build, tamper refusal, isolated extraction, and relocated launcher status. The existing Nx `knowledge-plugin-test` passed 2/2, including actual Registrar local-only intake and BM25 retrieval with one verified citation and zero Jev requests. Nx sync was current. The daemon initially omitted the newly added target from its cached project graph; `NX_DAEMON=false` resolved the new target and its test passed. That was an Nx discovery cache issue, not a release failure.

An isolated macOS Codex CLI local marketplace accepted the extracted archive, installed plugin version `0.1.0`, removed it and reinstalled it. From the extracted plugin, an external home installed Registrar, registered a synthetic local-only source, captured it and returned one expected cited BM25 result with `jevSharing: local-only` and `attemptedRequests: 0`. The launcher disabled that home and the reinstalled cached plugin still reported `disabled`. An initial test script assumed the Codex cache omitted its version directory; the actual path includes `0.1.0`. Correcting the test path confirmed the persisted selection; no product code changed.

This is a **private local release candidate**. The archive digest must reach a recipient over a trusted channel before extraction. The checked CLI path is macOS only; desktop Plugins Directory and Windows operation have not been tested. The external Knowledge home remains after plugin removal. A public license for the pinned Content Registrar source and reconciliation of its three downstream modifications are unresolved. The private bundle is not a claim of public distribution rights, hard revocation of already-running work, production losslessness, or completion of the five Knowledge production gates.

Independent review at `923aafd` found that the release checker accepted an otherwise valid, externally digest-pinned archive whose embedded plugin manifest said `dirty:true`, even though the packager refused to create one. Commit `08c133e` repaired the checker and added a forged canonical archive regression. The focused Nx run passed release 3/3 and plugin/actual Registrar 2/2, with Nx sync and formatting current. The independent reviewer found no remaining code Must-Fix at `8cbaded`. A reviewed archive from that clean commit had plugin manifest SHA256 `a2e4ed801d1219564eba03d10c75d657920e799504b84b40124f88f64ec1b9f4` and external archive SHA256 `75dedc0169606fa6217de4851357b1e3fd9b4fb2e8ada536b18a56430e781478`. Two builds were byte identical. The exact archive passed the checker and an isolated macOS recipient journey: one actual Registrar local-only intake, one verified cited BM25 result, zero Jev requests, CLI add/remove/reinstall, and a persisted disabled selection.

Review also identified a future versioning constraint: a changed source revision needs a new plugin version so Codex's versioned cache cannot confuse recipients. This first private candidate remains `0.1.0` and is identified by its external archive digest. The PR will pin its final commit and verification separately.
