# Private Knowledge release successor guard

The first private Content Registrar plugin bundle from [PR #201](https://github.com/randydinh/temari/pull/201) is version `0.1.0`. Its full Temari source revision is embedded in the plugin manifest, so a later clean commit can produce different bytes while still claiming `0.1.0`. Codex caches plugins under a versioned directory. Reusing the same version for changed content could make an upgrade ambiguous.

Two options were compared. Generating a commit-derived version would change plugin metadata and its source provenance contract. A successor check against a trusted prior release keeps the explicit plugin version and makes the release rule testable. The release tool now accepts `--prior-archive ABS --prior-sha256 HEX` together on `package`, and offers `check-successor` for two existing digest-pinned archives. It verifies both complete archives, permits an identical digest as an idempotent retry, and requires a strictly higher stable numeric SemVer for any changed archive. Malformed, prerelease, leading-zero and unsafe-integer versions refuse. The producer verifies a private staged archive before publishing it through an exclusive hard link. Failed writes, failed verification, and refused successors leave no final output on the tested POSIX filesystem; an existing output is preserved.

At clean candidate `bb85e1007c8007d345fb0697b5af35ff7c2ca3cf`, Nx `workflow-runtime:knowledge-release-test` passed 8/8, including changed same/lower version refusal, higher version and exact-digest acceptance, wrong prior digest, forged dirty source, and a POSIX file-size write failure. Nx `workflow-runtime:knowledge-plugin-test` passed 2/2, including actual Registrar local-only intake and cited BM25 retrieval with zero Jev calls. Nx sync passed. An actual new clean plugin artifact from that commit had manifest SHA256 `7bf0e0f8ffb22f4d557221aa804e3049dd1974e06f35d63eac409e3459d8587e`. Packaging it against the PR #201 archive pin `8cf8a4598f719ddeba7f7e64a0cf92d2ac54edfa22cb4b86034757b39649a01a` refused with “Changed release requires a higher plugin version than 0.1.0”; the requested final output did not exist. Independent review found no code Must-Fix at `bb85e10`.

The caller must supply the actual trusted prior archive and digest for each successor release. This tool cannot discover omitted releases, authorize a public distribution, or guarantee that a remote recipient uses the new bytes. The hard-link test proves atomic publication on this POSIX host, not native Windows behavior or power-loss durability. The next changed release must bump the plugin source version above `0.1.0` before packaging. Default Temari installation, Windows, public distribution terms, and the five production Knowledge gates remain open.
