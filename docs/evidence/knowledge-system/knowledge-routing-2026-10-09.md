composes it with Poteto engineering responsibility. Research alone selects no
engineering profile; QA retains its acceptance owner. Bounded evidence decisions
remain local context, with observed operation references or explicit missing-reference

## Neutral prompt trials

Five completed Codex CLI executions covered three prompt shapes. The prompts did
not name Knowledge or Poteto. Candidate skills were exposed through symlinked
repository `.agents/skills`, and a source-read-only Registrar MCP profile allowed
only one synthetic Cobalt policy source. No real OpConnect corpus, installed-plugin
cache change, source refresh outside the fixture, or optional Jev call was involved.
No model override was supplied. Unrelated host skill catalogs remained available;
this was not a model-isolated benchmark or a desktop-plugin activation test.

| Prompt shape | Independently observed behavior | Scope of result |
| --- | --- | --- |
| Cobalt heartbeat-loss reporting question | Knowledge loaded; bounded discovery and generation/hash-pinned policy read | Cited fictional project rule and unresolved assumptions |
| Explain current JS against Cobalt policy | Temari, Knowledge, intake and Poteto loaded; current code inspected and pinned policy read | Explanation only; no product edits or delivery profile claim |
| Rewrite one supplied sentence | No tool calls or external lookup | Correct direct response; no general skip-record interception demonstrated |

The initial research/engineering records summarized operations without concrete
result references. The reference was refined to require a result path/event ID or
`resultRef: null` with an explicit unavailable-reference limitation, and the exact
user request when no host request identity is exposed. Fresh executions of those
two prompts retained the exact requests and disclosed the unavailable references.
The independent reviewer checked actual completed events separately from authored
records. Initial engineering also performed unnecessary host resource-inventory
calls; those returned catalogs rather than private source evidence.

## Remaining boundary

The source increment and exercised synthetic CLI selection are verified. Model
records cannot themselves observe their host event IDs. A host observer still
needs to bind actual tool events to evidence decisions before mechanical
enforcement can depend on them. This increment does not intercept arbitrary chats,
execute Poteto stages/archive workers for research, or establish universal routing.

QA selection, web freshness, missing/disabled providers, broad corpus selection,
research-to-implementation transitions and general skip-record retention need
their own live cases. The user's installed cached plugins have not been replaced.
Use a versioned, verified install/update journey for activation; source edits do
not update installed caches. The separate uptime research chat retains its own
scope and evidence obligations.
