# Persistent Knowledge selection, 2026-10-02

The installed Knowledge launcher now treats Registrar as the default selection only when no selection file exists. Cold `status` reports that default without writing. Successful `setup` records a canonical, bounded `provider-selection.json` outside the plugin artifact and never resets an explicit disabled or disabling choice during repair or replacement of the plugin files.

`disable` verifies that any named Codex MCP entry matches the selected local installation, writes a durable `disabling` gate, then uses the bounded disconnect command. It records `disabled` only after Codex reports the entry absent. An uncertain inspection or removal returns a partial result and keeps the gate; retry can finish it. Foreign or changed entries found in the initial inspection are left intact. `enable` explicitly restores Registrar selection after checking the local installation and does not reconnect Codex. While disabled or disabling, the launcher refuses new delegated Knowledge commands and Codex connection before touching Registrar, a source, or a hosted model. Plain setup, status, disconnect, and help remain available.

One per-home advisory lock serializes setup, connect, disconnect, disable and enable, including Codex entry operations. These host controls require a local Python 3 with `fcntl`; native Windows is unsupported. The helper releases the lock on process crash; a second command waits at most five seconds before reporting busy. The tests interleave delayed Codex add and disable in both orders, overlapping enable, failed removal, busy lock and holder crash. The lock does not arbitrate different homes using the same fixed MCP name or out-of-band Codex edits. Codex remove still acts by name, and already-running Knowledge commands or MCP processes may continue. This is a persistent supported-entrypoint selection, not hard revocation, an external provider implementation, or an independently uninstallable plugin.

Final-source uncached `pnpm nx run workflow-runtime:public-entry-test --skipNxCache` passed 66/66; focused Knowledge cases passed 4/4, with syntax, public skill formatting and diff checks. An isolated real macOS Codex CLI 0.154.0 configuration returned `disabled` and showed the entry absent on a repeat run. It did not touch the user's Codex configuration or TypeSafe key. Native Windows/WSL2 was not exercised. Exact clean package and PR delivery remain pending.
