# Reconciler-managed source-head ledger, 2026-10-02

The existing refresh child job serializes one source and prior publication, but a different prior publication can have a separate job. A read-only design comparison considered reusing that child-task store, using the schedule store's occurrence ledger, a mutable source pointer under a writer lock, and an append-only source chain. Neither existing store owns a source publication head. This increment adds a separate runtime ledger whose immutable genesis and one reservation/terminal slot per prior publication form a bounded managed chain.

The ledger pins exact bytes for a caller-supplied publication claim, including selected source locator, task, registration and preservation fields. It does not validate the full Registrar manifest or current admission. One caller can reserve a prior publication for a changed-source capture; a competing cycle key conflicts. Its single terminal slot records either an advance with a byte-pinned, caller-supplied completion proof or a review hold. The runtime checks selected nested fields and hashes, but only a future Knowledge wrapper can establish full provenance against Registrar. A crash leaves a reservation in place; lease timeout does not free it. History permits 64 advances from genesis, then refuses the next reservation before it makes the ledger unreadable. The ledger is scoped to its configured trusted root and Temari-managed generations; it cannot see an out-of-band Registrar/operator capture or claim a global current head.

Repeated unchanged audits cannot consume the one reservation slot. A future Knowledge reconciler must run read-only freshness checks before reserving, then revalidate the exact managed head, current admission, completed audit and recapture handoff before advancing. This increment does not connect that wrapper, schedule recurring checks, mutate the graph, or call TypeSafe.

The final scoped runtime check passed 274/274 tests, including competing reservations, a hold/advance race, stale-head refusal, tampered proof, an overlimit artifact, and the exact 64-advance boundary. Runtime typecheck, Nx sync, scoped formatting and diff checks also passed. Independent review caught the terminal-slot, chain-bound and bounded-read defects in earlier drafts; they were fixed before delivery. No actual Registrar or Knowledge integration ran for this low-level ledger-only increment, so no end-to-end source cycle is claimed.
