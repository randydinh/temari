# Declared DOCX header/footer DrawingML references

This separate Knowledge adapter accepts an explicitly recovered original for one complete, pinned Registrar publication. It runs the existing bounded DOCX package-media inventory first. It then reads direct `w:headerReference` and `w:footerReference` declarations in `w:sectPr`, resolves matching internal relationships from `word/_rels/document.xml.rels` to safe `word/header*.xml` or `word/footer*.xml` parts, and maps DrawingML image references in each selected part through that part's own relationship file to verified `word/media/*` hashes and byte counts.

The metadata-only receipt keeps repeated declarations as separate rows, while parsing a selected part once. It records relationship ID hashes, selected part names, mapped media hashes and byte counts, and explicit gaps for missing/external/wrong-type declarations and linked, unresolved or absent media references. The field `notReferencedBySelectedHeaderFooterParts` is scoped to **these selected parts**. It may include a media member used by the document body or another DOCX part; the fixture includes a body-only image to demonstrate this distinction. The receipt includes the base media receipt digest and worker/adapter hashes, with current admission, publication, base receipt and bounded recovered-original rechecks before publication.

The fixed Python standard-library worker is run with `-I -S`, a 30-second timeout and 1 MiB output bound. The original and package retain the media adapter's 8 MiB compressed original, 1,000 ZIP member, 32 MiB actual expansion, 256 media, duplicate-name and CRC checks. This worker allows at most 256 direct header/footer declarations, 32 unique selected parts, 256 total DrawingML blips in those parts, 1,000 relationships per XML relationship part, 1 MiB per XML part and 8 MiB cumulative XML. It requires exact expanded OOXML namespace names and valid document, selected header/footer and relationship roots. Internal relationships accept only canonical raw relative targets; percent-escaped, package-root URI, dot-segment, backslash and control-character targets deliberately refuse, even when a different DOCX reader might accept them. Malformed XML, DTD/entity declarations, duplicate relationship IDs, unsafe internal paths and limit breaches refuse. Raw XML, alternate text, image bytes, external URLs and the recovered path are absent from the receipt.

## Actual Registrar evidence

The local-only fixture captures a synthetic DOCX, removes its live original, explicitly recovers it, and checks repeated header declarations, a footer declaration, matching part relationships, repeated image references, separate per-part relationship IDs, mapped media SHA-256s, gaps and the scoped residual-media field. It tests unsafe document and part targets, duplicate part relationship IDs, DTD and malformed roots, reference and selected-part limits, cumulative XML limit, tampered recovered bytes and disabled registration. Final check counts and PR identity are recorded in the append-only overnight decision log.

`coverage: declared-header-footer-drawingml-only` reports syntax in selected parts. It does not resolve section inheritance, determine which header or footer Word renders on a page, interpret visual meaning, cover VML/charts or other DOCX parts, or establish Windows or production losslessness.
