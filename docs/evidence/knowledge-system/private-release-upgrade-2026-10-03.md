# Private Knowledge release upgrade validation

The clean 0.1.1 plugin artifact from the Registrar upstream sync initially could not be packaged against the trusted 0.1.0 archive. The release checker validated both archives against the **current** Registrar `UPSTREAM.json` pin, so it refused the valid earlier release after the upstream pin advanced. The first packaging attempt published no final output.

The repair separates candidate and prior validation. The current candidate still requires this checkout's exact Registrar manifest and commit pin, generated marketplace and README, clean source revision, nested runtime integrity and canonical release bytes. A prior release is accepted only after the caller supplies its complete archive and independently trusted SHA-256; the checker verifies that digest, canonical archive, `RELEASE.json` inventory, plugin manifest, nested Registrar files and hashes, runtime manifest, clean source revision, and version identity. Historical marketplace policy may be `AVAILABLE` or `INSTALLED_BY_DEFAULT`, while all other identity, source, authentication and category fields remain exact. Historical README text must be bounded, readable and bound to the recorded version, revision and plugin manifest hash. Ordinary exported plugin and Registrar validators retain their strict current-pin contract.

Two approaches were compared. A version-only prior receipt would add a second trust artifact and bypass verification of the actual earlier bundle. Checking the externally digest-pinned prior archive with its own nested provenance preserves one trust root while letting reviewed payload pins and catalog copy change across releases. A fully self-consistent forged archive with an attacker-chosen new digest cannot be distinguished from a trusted prior; the caller must obtain the prior SHA-256 through a trusted channel.

At the uncommitted repair candidate, Nx release tests passed 12/12 and the relocated plugin tests passed 2/2, including synthetic local-only Registrar intake and cited BM25 retrieval with zero Jev calls. The local real-prior test used the PR #201 archive with SHA-256 `8cf8a4598f719ddeba7f7e64a0cf92d2ac54edfa22cb4b86034757b39649a01a`; it skips where that private artifact is absent, while portable synthetic historical cases remain. Tests cover strict current-candidate refusal for old Registrar pins, wrong prior digest, malformed inner inventory/catalog/README, changed same-or-lower version, and failed-publication cleanup. Independent review found no Must-Fix in the final working diff. A clean pinned commit, actual 0.1.1 successor package, recipient journey, and exact-head review remain required before delivery.

This is a private distribution check. It does not establish public license rights, default Temari installation, native Windows operation, real Lima PDF extraction, hosted-model answer quality, or any of the five production Knowledge finish gates. Direct TypeSafe Jev remains the only hosted model; local-only sources do not call it.
