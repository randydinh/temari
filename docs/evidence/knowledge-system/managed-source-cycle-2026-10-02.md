# One reconciler-managed source cycle, 2026-10-02

The one-shot freshness audit can observe a changed source, and the linked refresh job can recapture one pinned prior generation. The runtime source-head ledger from PR #194 can reserve and advance a managed publication chain. This increment connects those pieces only for a completed `recapture-needed` audit. Repeated read-only `unchanged` observations do not consume a source reservation.

The wrapper checks the prior complete publication, current registration and Registrar generation, and the original local binding/attempt/result. It refuses an imported, rebound, OCR, PDF-worker or custom-limit prior capture when its recapture policy cannot be carried forward exactly. It reserves the managed head before invoking the linked refresh job, leaves an active or transiently uncertain cycle reserved, and advances only after a complete pinned handoff and current admission check. A terminal blocked refresh is held for review and may already have caused a Registrar capture. Graph impact, when requested with a prior graph pin, remains a plan for review; the graph is not mutated.

The ledger is rooted in the trusted task directory and governs only reconciler-managed generations for that root. Another task or operator can capture the same Registrar source outside this ledger. A current registration check and a later capture are not atomic with such out-of-band work. `observed-unchanged` and `audit-needs-review` are point-in-time audit outcomes, not a global currentness or source-wide pause guarantee. There is no recurring trigger or automatic graph correction here.
