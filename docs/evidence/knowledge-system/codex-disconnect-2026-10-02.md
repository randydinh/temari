# Bounded Codex Knowledge disconnect, 2026-10-02

The bundled Knowledge launcher now offers `disconnect-codex`. It checks the named `temari-content-registrar` stdio configuration against the selected home and workspace, reads it a second time, removes it by name, then verifies absence. A missing entry is already disconnected. Mismatched configuration, unknown inspection output, failed removal and a still-present entry refuse or report failure without printing captured Codex configuration or stderr. The command does not need an intact Registrar installation and does not delete the local virtual environment, registry, archives, credentials or task artifacts. The existing `connect-codex` restores access when setup remains valid.

Codex CLI `mcp remove` has no conditional expected-value operation. Another process can replace the same named entry between the final matching read and removal; that changed entry may still be removed. Post-removal inspection can also become uncertain if another process changes it. This command is a bounded host control, not an atomic ownership guarantee, a provider selection state, a complete Knowledge disable, or independent plugin uninstall.

On the final source, uncached `pnpm nx run workflow-runtime:public-entry-test --skipNxCache` passed 64/64, including relocated install, matching and mismatching entry cases, local data retention and reconnect. An isolated real macOS Codex CLI 0.154.0 config under `/private/tmp` accepted a synthetic matching entry; the launcher returned `disconnected`, then `already-disconnected` on repeat. That smoke used no user Codex configuration or Registrar credential. Native Windows/WSL2 was not exercised. Clean package and PR delivery are pending.
