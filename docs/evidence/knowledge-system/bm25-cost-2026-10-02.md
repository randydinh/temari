# Fixed-source BM25 component diagnostic, 2026-10-02

## Hypothesis and setup

The earlier synthetic scale run changed the number of registered sources as the
document count grew. This opt-in diagnostic holds registration at **one
local-only source** and measures three pinned generations with 100, 500 and
1,000 small text documents. It asks whether the current `_bm25_rank` helper
accounts for most of the time in a bounded Registrar discovery. It does not
change the ranker, add a cache or set a latency target.

`tools/bench-archive-bm25-components.py` uses the actual bundled Registrar.
All captures and full original/text-representation inspections finish before
timing. Every generation is queried with the same two-term query, source ID,
top-three limit and 16,000-byte response cap. Each route receives one warmup
and seven monotonic-clock samples:

1. Fresh CLI processes measure startup plus pinned discovery.
2. In-process `SourceRegistry.discover_snapshot` calls measure pinned discovery.
3. A process-local wrapper times `_bm25_rank` within those same in-process
   calls, restoring the original helper in `finally`. The paired residual is
   in-process total minus that helper time.

After each response, an independent archive read checks the top citation's
source, generation, manifest, path, original and representation hashes, quote
and code-point span. These reads are outside the timers. The selected index
digest must remain identical across warmup and timed calls within each
generation and across routes. The run verified 48 top citations and all three
selected indexes. The raw host details and sample series are retained only in
the private local report; its SHA-256 is
`936ea3e1f28c3f45a1672e9582064d727528577b75b1ff0378df130809d8c18c`.

## Observed time

Measurements were on one macOS arm64 host with Python 3.12.13 and SQLite
3.53.1. Times are milliseconds. `p95` is the nearest-rank value from seven
samples, so it is the largest sample and is unstable as a tail estimate.

| Documents | Selected text + path bytes | Fresh CLI median / p95 | In-process median / p95 |
| --------: | -------------------------: | ---------------------: | ----------------------: |
|       100 |                     55,766 |      127.202 / 130.252 |         41.401 / 43.140 |
|       500 |                    278,566 |      912.024 / 941.202 |       846.399 / 864.362 |
|     1,000 |                    557,066 |  3,355.173 / 3,534.363 |   3,276.202 / 3,352.412 |

| Documents | BM25 helper median / p95 | Paired residual median / p95 |
| --------: | -----------------------: | ---------------------------: |
|       100 |            0.656 / 0.688 |              40.718 / 42.484 |
|       500 |            1.915 / 1.949 |            844.449 / 862.535 |
|     1,000 |            3.421 / 3.571 |        3,272.781 / 3,349.006 |

The bounded helper consumed little of this in-process time. The residual is
mixed non-rank overhead: archive validation, representation reads, selected
index preparation, response assembly and Python work all remain in it. It is
**not** a measurement of validation alone. `_bm25_rank` itself includes its
bounds checks, temporary in-memory SQLite FTS5 setup/query and Python result
sorting; the wrapper does not isolate SQL execution.

The CLI and in-process blocks ran sequentially. Cache state and order can
affect either, so their difference is **not** an isolated startup cost. This
single deterministic synthetic corpus, rare-term query and seven-sample host
run do not establish production latency, retrieval quality or a service-level
objective. The run made no hosted-model call and did not access a credential.

## Reproduction and verification

Run the diagnostic explicitly with a Registrar-capable Python and a new report
path outside the repository:

```sh
python3 tools/bench-archive-bm25-components.py \
  --counts 100,500,1000 --warmup 1 --repetitions 7 \
  --output "$TMPDIR/temari-bm25-components-report.json"
```

The report contains exact sample and host details and must remain private.
There is no CI timing gate or automatic ranker promotion. A 5/10/20 document
smoke passed before the full run. Nx verification results for this diagnostic
are recorded in `libs/knowledge/VERIFICATION.md`.
