## D-2026-09-21-01: One local conversation draft caller owns exact replay

Status: accepted

Keep `createConversationPlanDraft` in `@temari/plan-draft`, which already owns
the authorized local file effect. One command supports start and resume through
five immutable task-local records: `started`, `investigated`, `proposing`,
`proposed`, and `reviewing`. They pin the original inputs, actual investigation
result, proposal, provider identity, and judgment identities and revisions.
Knowledge and draft results remain separate.

Reject separate public investigation, preparation, and publication methods for
this caller. They would require every host to rebuild the same durable handoff
and recovery protocol. Reuse the existing draft engine and narrowed private
admission functions, without a new orchestration package or duplicate preparation
schema. Exact authority, configuration, and known output conflicts are checked
before judgment. Conversation sources remain untrusted evidence.

Only the creator of the `reviewing` marker can invoke independent review. The
marker binds the proposed record and exact candidate hash. On retry,
`createLocalPlanDraft` bypasses the review wrapper when valid accepted preparation
exists. Without that preparation, an existing review marker blocks repetition.
An unsaved investigation or proposal outcome also blocks. Preserve the artifacts;
do not regenerate judgments or claim exactly-once execution or universal recovery.

This decision leaves knowledge ownership, agent topology, deployment, storage
policy, and the broader product experience open. The application supplies real
assessment, proposal, and review services. `checkReady` checks configuration only.
Host model dispatch and automatic authority creation are not implemented here.
Identities are caller assertions under the trusted cooperating local process
profile, not authentication.

## D-2026-09-21-02: Local commands supply replaceable judgments

Status: accepted

Add `createCommandJudgments` to `@temari/plan-draft`. A trusted deployment
selects pinned commands for assessment, proposal, and review. One private module
owns role policy and structural decoding; the factory owns identities, readiness,
JSON framing, and bounded child execution. Existing callbacks, citation and
exact-content admission, authority, journals, and publication remain intact.

Choose this concrete boundary over another injected transport interface. It
provides executable integration and bounded failure behavior now, without a
second host implementation, provider SDK, registry, or new package. Service IDs
and configuration revisions are opaque assertions. No provider or model taxonomy
is required. Construction performs no I/O, so saved accepted preparation can
recover without live commands. Invocation failures never retry or repair results.

Accept the cost of a POSIX process protocol. The command exchange has a deadline;
readiness and artifact hashing do not. Failure terminates the owned process group
with bounded grace, but cannot contain escaped descendants or cancel remote work.
Commands are trusted host code. Artifact pins do not establish dependency closure,
and fresh processes do not prove independent reasoning or historical sessions.
The bridge passes declared environment values and suppresses implicit Node
coverage forwarding. Operating systems and child runtimes can synthesize values.

Real child-process tests and an actual Registrar composition use synthetic
judgments. They verify transport, admission, exact bytes, and recovery. Live
semantic quality and authorization for a provider and data corpus remain separate
gates. This decision does not activate a service or complete FT/CP/CX validation.
