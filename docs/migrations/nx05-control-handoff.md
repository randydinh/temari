# NX05 milestone 1 control handoff

This increment defines a command-only control and artifact contract for a future shared provider. It retains a synthetic, separate-process recovery suite for the existing file stores. The shared-provider conformance gate is **BLOCKED**. No shared provider, remote dispatcher, or multi-machine test exists. The workflow engine remains the sole lifecycle authority.

## Contract and observed behavior

`Nx05FileProcessAdapters` groups the existing file stores only for the one-host process fixture. Its scope is always `single-host-file`. Its raw `runs` and `children` methods are not a shared control API. `Nx05SharedControlProvider` has no raw store properties. A type-level check rejects treating the file adapter as a shared provider and rejects restoring raw store properties to the shared interface.

The shared contract names service-time claim, renewal, and cancellation methods without caller-supplied `now`. `commitParentAndDispatch` carries the next parent status, event type and payload, and dispatch intents in one request. A provider must atomically persist all three under the current owner, token, and fencing epoch. `publishChild` carries the terminal child status and complete result or mechanical error. A successful worker result requires portable artifact references. A provider must verify every referenced artifact is present and hash valid before committing the child result under its fence. A repeated idempotency key must return the same committed result only for the same complete command; changed payloads must fail. The immutable artifact provider returns path-free references and verifies bytes on load. These are requirements for a future implementation, not behaviors exercised by this branch.

The file parent store now requires the current owner and lease token for a new event while the run is `RUNNING`. It refuses new events after a terminal transition. Parent transition replay compares the entire committed payload, including keys omitted by a retry. These two local fixes passed separate-process adversarial tests. The file child store still accepts a shape-valid `SUCCEEDED` result with an unwritten artifact reference because `complete` does not load artifact bytes. The process test records that exact counterexample. The file adapter cannot satisfy the shared publication invariant, so a green process suite is not a shared-conformance PASS. The premise and ownership census is in [NX05 invariant census](nx05-control-invariants.md).

The file parent store uses its increasing `attempt` as the observed ownership epoch and a random lease token as its write fence. The child store has an explicit `fencingEpoch`. The process suite observed attempts and epochs increasing from 1 to 2 after lease expiry, rejected stale owners, and replayed one terminal operation without a duplicate event. It also observed two simultaneous group claimers respecting a maximum of two active child leases.

Each fixture invocation starts a new Node process and opens the same local directories. One process claims work and exits. A later process reopens the stores after a synthetic clock advance, reclaims work, and rejects the former owner's completion. At code commit `15a8b6e0e0afa515490e23106fc2cab9ed694e3e`, the focused run recorded parent claim PID 21895, parent restart PID 21901, parent attempt 2, child claim PID 21940, child restart PID 22046, and child epoch 2. Those PIDs are one observation, not stable expected values.

The crash test interrupts commits after sidecar sync, state publication, event publication, and sidecar removal. A new process reconciles each stage for both parent and child stores, then reclaims after the injected lease expiry. The artifact load test refuses changed bytes or a missing file. The publication test demonstrates a different path: child completion succeeds before any bytes exist. These observations establish only local process recovery with synthetic time. They do not establish service durability, host independence, or real-time lease behavior.

## Open gates

The shared-provider conformance gate remains BLOCKED in milestone 1 because no service implements the command-only interface and the file child completion counterexample remains. The current runtime still uses raw child completion and saves a parent receipt before its leased transition. A later integration must migrate those callers to the fenced provider path and prove the atomic parent state, event, and dispatch commit plus artifact validation before child publication. An interface alone does not enforce either behavior.

Milestones 2 through 4 remain open after NX03 is integrated. They need a selected transactional control service, an immutable shared artifact service, explicit durability and backup assumptions, remote at-least-once dispatch, fenced receipt and checkpoint publication, and workspace recovery policy. Independent QA must review the integrated path. A second host with an independent disk and a shared external service is required before any multi-machine claim. Automatic failover, production RTO and RPO, and exactly-once external effects are outside this milestone.

The branch is for independent review. Do not treat the file adapter as a shared service or this process result as a cutover approval.
