# NX05 milestone 1 control handoff

This increment defines the control and artifact interfaces for a later shared provider. It also adds a synthetic, separate-process conformance suite for the existing file stores. The file stores remain local to one host. This increment does not dispatch remote workers or change the workflow engine.

## Contract and observed behavior

`Nx05ConformanceAdapters` groups the existing `WorkflowRunStore`, `ChildTaskStore`, and `EvidenceStore` interfaces. `openNx05FileConformanceAdapters` identifies its scope as `single-host-file`. The process fixture uses that adapter. A later shared adapter can use the same operation sequence, but it must provide its own service and host tests.

`Nx05SharedControlProvider` adds two operations that the file adapter does not implement. `commitParentAndDispatch` must atomically commit the parent state, event, and dispatch intents under a live fenced lease. `publishChild` must reject stale epochs and absent or hash-invalid artifacts before it commits a child receipt. The shared control provider must use service time for lease decisions and fenced compare-and-swap writes. The immutable artifact provider must return portable hash references and verify bytes on load. Idempotency keys must replay the same result and reject changed payloads. Cancellation must remain durable and visible to the one workflow engine.

The current file parent store uses its increasing `attempt` as the observed ownership epoch and a random lease token as its write fence. The child store has an explicit `fencingEpoch`. The process suite observed attempts and epochs increasing from 1 to 2 after lease expiry, rejected stale owners, and replayed one terminal operation without a duplicate event. It also observed two simultaneous group claimers respecting a maximum of two active child leases.

Each fixture invocation starts a new Node process and opens the same local directories. One process claims work and exits. A later process reopens the stores after a synthetic clock advance, reclaims work, and rejects the former owner's completion. At code commit `15a8b6e0e0afa515490e23106fc2cab9ed694e3e`, the focused run recorded parent claim PID 21895, parent restart PID 21901, parent attempt 2, child claim PID 21940, child restart PID 22046, and child epoch 2. Those PIDs are one observation, not stable expected values.

The crash test interrupts commits after sidecar sync, state publication, event publication, and sidecar removal. A new process reconciles each stage for both parent and child stores, then reclaims after the injected lease expiry. The artifact test loads by portable hash in a second process and refuses changed bytes or a missing file. These results prove local process recovery with synthetic time. They do not prove service durability, host independence, or real-time lease behavior.

## Open gates

Milestones 2 through 4 remain open after NX03 is integrated. They need a selected transactional control service, an immutable shared artifact service, explicit durability and backup assumptions, remote at-least-once dispatch, fenced receipt and checkpoint publication, and workspace recovery policy. Independent QA must review the integrated path. A second host with an independent disk and a shared external service is required before any multi-machine claim. Automatic failover, production RTO and RPO, and exactly-once external effects are outside this milestone.

The branch is for independent review. Do not treat the file adapter as a shared service or this process result as a cutover approval.
