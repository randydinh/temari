# v4.1 to Nx compatibility matrix

This matrix is the migration boundary for the portable Temari and pstack
workflow. It records what is carried, what is translated into the Nx control
plane, what remains an external overlay, and what still needs proof before
cutover.

## Baseline

- Portable v4.1 source revision: `959c8f7be3d7b684207d9e626263d41540d5ecdc`,
  recorded in `packages/workflow-runtime/provenance.json`.
- Nx repository baseline: `057e65e`, the `main` head used when this matrix was
  started.
- Canonical engine: `libs/workflow-engine`.
- Canonical semantic planning boundary: `libs/temari-core` and
  `libs/contracts`.
- Rollback: retain the packaged v4.1 distribution until the cutover gates in
  `docs/temari-nx-cutover-plan.md` pass. This matrix does not authorize removal
  of the old distribution or any external overlay.

The compatibility rule is strict. A v4.1 record is not an Nx success merely
because it parses. Version, source identity, ownership, capability provenance,
evidence, and the explicit unsupported boundary must remain visible.

## Required WP1 decisions

The next contract increment must define these shapes before it imports more
behavior:

1. A versioned v4.1 profile and route record that preserves source revision,
   profile identity, route identity, capabilities, assignments, and explicit
   unsupported reasons.
2. A conversion result that distinguishes `supported`, `blocked`, and
   `incompatible` rather than returning a partial `ExecutionPlan` as if it were
   valid.
3. Capability provenance that distinguishes a declaration from a live proof.
4. Redacted credential references and overlay metadata without secret values.
5. Sanitized fixtures for valid, stale, malformed, and unsupported records.

These contracts should be added only after their consumers and verification
gates remain aligned with this matrix.

## Cutover gate

Migration is ready for the next phase when every carried row has a target,
owner, verification command or fixture, and rollback note. Final cutover still
requires the shared-service parallelism proof, public package proof, clean-host
journey, drift result, observation period, and explicit rollback evidence.
