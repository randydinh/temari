# Triage: <issue or symptom>

## 1. Symptom and scope
- Report/source revision; user outcome; environment/build/candidate; time/frequency; affected scope and unknowns.
- Duplicate/related history, search coverage, existing owner, and distinct issues to split.

## 2. Expected versus observed
- Requirement/decision reference, revision and authority → expected outcome.
- Reported versus directly observed facts; exact reproduction preconditions/steps and evidence; attempt status and comparison limits.

## 3. Mechanism and confidence
- Repository/commit and working-tree differences; source references, entry point, callers and boundaries.
- Retained summary (revalidated or pending), inference, alternatives and counterevidence.
- Confidence in the mechanism separately from incident attribution; next discriminating check.

## 4. Impact and disposition
- Classification; user impact, reachability, scope and workaround limits.
- Severity with external scale/owner, or unassigned; priority as a separate owner decision.
- Recommendation and rationale; no implication of QA acceptance or verified repair.

## 5. Action and open work
- Next action → owner, required input, expected artifact and completion check; focused repair/regression handoff when applicable.
- Blocker request when needed: **Established:** … **Still needed:** … **Who:** … **Why:** … **Meanwhile:** … **Resume check:** …
- Preserve full QA scope, blocked/unrun scenarios and evaluation obligations; route verification notes or defect formatting to the existing writer.
